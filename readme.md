# Система бронирования аудиторий внеучебного фонда университета

Информационная система бронирования и наполнения внеучебных аудиторий: веб-сервис для менеджеров
залов, электронные афиши на планшетах, контроль пересечений по времени, роли и белые списки IP.

Выпускная квалификационная работа.

## Зачем это нужно

Залы принадлежат разным организациям и ведутся отдельными модераторами. Заявки собирались
вручную, пересечения по времени отслеживались на глаз, на дверях не было актуальной информации.
Система решает три задачи:

1. Принимает заявки и записи в залы и не допускает двойных броней.
2. Даёт каждому залу своих модераторов с возможностью временно передавать права.
3. Показывает на планшете у двери зала, что было, что идёт и что будет.

## Возможности

| Этап | Содержание |
|---|---|
| 1. Основа | Корпуса, залы, роли, модераторы залов, записи с контролем пересечений |
| 2. Афиша | Страница для планшетов: прошедшее, текущее и следующее мероприятие |
| 3. Онлайн-заявки | Подача заявки пользователем, очередь модератора, одобрение и отказ |
| 4. Передача прав | Временное делегирование модерации (отпуск, замена) |

## Роли

| Роль | Что может |
|---|---|
| Пользователь | Просматривать залы и календарь, подавать заявки, отменять свои |
| Модератор зала | Рассматривать заявки своих залов, записывать людей вживую, передавать права на срок |
| Администратор | Всё: корпуса, залы, пользователи, назначение модераторов, экраны, белые списки IP |

Модератор это не глобальная роль, а назначение на конкретный зал со сроком действия.

## Настройки и запуск

- Для запуска API на хосте скопируйте `.env.example` в `.env.local`.
- Для Docker Compose скопируйте `.env.docker.example` в `.env`.
- Замените пароли и оба JWT-секрета. Пароли в URL должны соответствовать отдельным настройкам; специальные символы в URL нужно кодировать.
- Секреты передаются контейнеру через `env_file`, в образ не копируются.

```powershell
docker compose up -d db redis
docker compose run --rm api alembic upgrade head
docker compose up -d api
```

API: http://localhost:8000/api/docs

SMTP и Celery оставлены в текущем состоянии; worker в Compose не запускается.

## Списки заявок и доступных залов

- `GET /api/bookings/my` — заявки, созданные текущим пользователем. Идентификатор владельца берётся из авторизации; superuser здесь также видит только свои заявки.
- `GET /api/rooms/my` — залы с действующими назначениями текущего модератора. Superuser получает все залы по фильтрам. Используются обычные фильтры залов; по умолчанию выбираются активные, `is_active=false` выбирает неактивные.
- `GET /api/rooms/{room_id}/booking-requests` — подробный список заявок зала, доступный только его модератору и superuser.

Все три списка возвращают `items`, `total`, `page`, `size`, `pages`. Размер страницы — от 1 до 100.
Списки заявок принимают повторяемый параметр `statuses`, необязательные `room_id`, `start_at`, `end_at`.
Без дат возвращается история за всё время. Период относится ко времени мероприятия: `end_at > начало фильтра AND start_at < конец фильтра`.
Даты передаются с часовым поясом. Порядок заявок: `created_at DESC, id DESC`.

Архив: `/api/rooms/1/booking-requests?statuses=rejected&statuses=canselled&page=1&size=20`.
Значение `canselled` сохраняет существующее написание статуса в БД/API.
Календарь `/api/rooms/{room_id}/bookings` по-прежнему отдаёт только подтверждённые записи, а модератору также ожидающие; архив в него не включается.

## API

Создавать корпуса, подразделения и форматы мероприятий может только superuser. Чтение справочников публичное.

Все ошибки имеют формат `{"detail": "текст"}`, включая ошибки валидации, авторизации, 404 и внутренние ошибки. Подробности внутренних ошибок остаются в серверных логах. Для валидации возвращаются пути полей и сообщения без исходных значений запроса.

Отчество необязательно. Для онлайн-бронирования необходимы заполненные имя, фамилия и телефон. Подразделение в профиле может отсутствовать.

## Проверка

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

Проверки API выполняются без внешних сервисов с подменой зависимостей. Миграции и ограничения пересечений необходимо дополнительно проверять на отдельной PostgreSQL.
